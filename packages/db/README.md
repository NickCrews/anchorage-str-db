# `@anchorage-str-db/db`

The DuckDB database, and the only package that uses DuckDB directly.

- `schema/`: the tables, as Drizzle `pgTable` definitions, one file per
  source: `airbnb.ts`, `muniLicenses.ts`, `muniGis.ts`, and
  `muniStrRegistry.ts` for the archived registration layer. Each holds its
  source's data as published. `index.ts` exports them all.
- `views/`: the views, as DuckDB SQL. `airbnb.ts` and `muniLicenses.ts` read
  one source each; `combined.ts` joins them. `licenses` is each visible
  license's latest page read; `registrations` is one row per STR Certificate
  number on a Short-Term Rentals license, with the license's geocode and
  parcel type, falling back to the archived registration layer's geocode.
  `index.ts` has `viewsSql`, which creates them all.
- `connect.ts`: `connect(path)`, which applies the migrations, checks the
  tables and recreates the views
- `database.ts`: `Database`, a wrapper over one connection with raw SQL,
  `appendRows` for bulk inserts, `transaction`, and `orm` for Drizzle queries
- `drizzle/`: migrations generated by `drizzle-kit` from `schema/`

Drizzle has no DuckDB dialect, so the schema uses `drizzle-orm/pg-core` and
[`@duckdbfan/drizzle-duckdb`](https://github.com/leonardovida/drizzle-duckdb)
runs it on DuckDB.

An ingest app imports only its own source's files, e.g.
`@anchorage-str-db/db/schema/airbnb`.

```sh
pnpm --filter @anchorage-str-db/db generate --name <change>
```

See [CONTRIBUTING.md](../../CONTRIBUTING.md#changing-the-schema) before
changing a table.
